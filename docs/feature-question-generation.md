# 功能一：RAG 面试题生成

状态：方案已确认，代码按下面的决定实现。多路召回、重排和召回率评测留到有测试集之后。

复现按三个功能推进，一次只做一块。

1. RAG 面试题生成。简历对应：多路召回、数据治理、召回准确率 72%→90%。
2. 实时语音面试与评分。简历对应：ASR → ReAct 追问 → Qwen 评分，主观分差 <10%；Celery 报告/评估队列从分钟级到秒级。简历原文「React」按 ReAct 理解。
3. 多 Agent 综合评价报告。简历对应：LangGraph 上初试 / 复试 / 综合评估，MCP 与多跳检索汇聚证据，结构化录用报告。

当前代码里的文字初试切片只是走通界面，不代替功能一。

## 线上行为（实现时以此为准）

面试题生成在简历评估之后、语音初试之前。使用者是 HR、部门负责人、JD 专员。团队负责人只能看已生成列表。

入口在侧栏「语音面试 → 面试题生成」。

- 路 A：人员列表里对已通过简历评估的人点「邀请面试」，带上评估 ID、姓名、公司、部门、岗位、JD 编码。
- 路 B：面试题生成页先看已生成 / 待面试 / 已完成。点「生成新面试题」去人员列表选人，或手填评估 ID 再查询。
- 人员未确认时，「生成面试题」为灰色。

默认一场 40 分钟、15 道题。

- 基本信息题 5 道、10 分钟：稳定性、沟通协作、抗压、学习自驱；管理岗另含团队领导力。
- 专业技能题 10 道、30 分钟：业务知识、项目经验、技术深度、工具系统、综合方案。

生成前可改：两类时长（基本信息 0～120、专业 10～180，步进 5）、两类题量（各自 0～30，合计至少 1）、初级/中级/高级数量（三者之和等于总题数）、考察重点。改题量时先把难度均分。

岗位资料按公司 + 部门 + 岗位。可上传 PDF、Word、Excel、TXT、PPT，单文件不超过 5MB。上传后解析、分块、向量化，能看到文件名、来源（本岗位 / 岗位模板）、分块数、更新时间。默认不勾选文件，本次出题不读岗位资料。没有勾选时专业题仍可由模型和通用题库生成。

界面上隐藏、后台默认：题目来源为全部由 AI 生成；基础五类和专业五类都启用。管理岗才使用团队领导力。综合方案按岗位过滤。

生成步骤展示为：解析 JD 与简历、按关键词召回并过滤、生成基础题、生成专业题、整理评估要点和参考答案。成功后题目默认全选。第一次生成建立草稿邀请，再次生成覆盖这条邀请上的题目。

审题分两张表。基本信息题展示类别、题干、难度、预估时长、评估要点（含权重），操作为替换。专业题多来源（AI 生成 / 题库）和参考答案。AI 题可改题干并重算评估要点。题库原题不能改字，只能替换。替换从相似题里选，展示相似度和使用次数。未勾选的题不进入正式面试。

底部：取消、保存到知识库、发起面试。后两项至少勾选一道。

- 保存到知识库只入库，不改面试状态，不发账号。
- 发起面试保存勾选题目，邀请变为已确认，生成候选人账号和 8 位数字密码，弹出姓名、岗位、账号、密码、登录地址，可复制。密码只在这一次明文展示。列表里的「复制」可以再取登录信息。

已生成列表可查看、复制、导出、重置。仅重置状态回到草稿并清掉账号密码，题目保留。完整重置清掉题目、答题、评估和账号。

上游输入是该评估 ID 下的 JD（职责、要求、必备/加分项）、简历原文，以及可选岗位资料。这一期不存 21 维评估结论。每题带评估要点和权重，供后续语音评分使用。对同一条邀请再次生成会覆盖上一轮题目，并清掉已发出的账号密码。

## 已确认方案

界面是企业 HR 后台：深海军蓝侧栏，白色和浅暖灰工作区，表格和卡片为主。AI 只用蓝色标签和很浅的高亮，不用高饱和渐变。这一期的「发起面试」只生成账号、8 位密码和登录地址。候选人打开链接后核对账号密码，看到已勾选的题干。不进入语音房间。

数据用虚构电力岗位：山东鲁软营销部电费核算（周宁、赵敏）、北京南瑞调度部调度自动化（李衡）。表包括岗位 JD、候选人简历、岗位资料、面试题库切片、出题参数、邀请和题单。没有 21 维字段。

检索按这个顺序，只有一条关键词路径：

1. 上传 PDF、Word、xlsx、TXT、PPT。单文件不超过 5MB。老的 xls 需要另存为 xlsx。
2. 按标题和段落切片，去掉短于 20 字和内容重复的块。每块保存原文、标题、公司、部门、岗位、资料类型。
3. 本机用 bge-m3 写入 1024 维向量。向量先入库，这一期出题不拿向量做召回。
4. 用候选人岗位、简历、JD 要求和考察重点抽出关键词，在全部切片里做子串召回。
5. 再过滤：公司、部门、岗位必须一致；同一岗位的题库保留；岗位资料只有被勾选才保留。
6. 按命中词数取 Top 6，拼进 Qwen 的出题提示词。

出题走 Qwen 兼容接口。密钥读环境变量 `Qwen_API_KEY`，没有时再读 `DASHSCOPE_API_KEY`。默认地址 `https://maas.qianwenaiapi.com/compatible-mode/v1`，默认模型 `qwen3.8-flash`。为了稳定拿到题单，请求是非流式 JSON，并关闭思考过程。缺密钥或模型失败时接口返回错误，不用模板题冒充。

暂不做：BM25 与稠密向量的两路召回、RRF、bge-reranker、Recall@5 界面数字。简历上的 72%→90% 在对上分子、分母和样本之前不写进界面。

## 已确认的五件事

1. 召回率以后可以用 Recall@5。当前没有标注过的出题查询，界面不报这个数。72%→90% 的统计对象还没对齐。
2. 在个人电脑的 WSL 安装 PostgreSQL，并使用 pgvector。仓库提供 Docker Compose。
3. 对话密钥放在本机环境变量。嵌入用本地 bge-m3，不调用向量接口。
4. 人员和岗位用虚构电力夹具，不放 21 维结论。
5. 发起面试只到账号、密码、链接和题单。
